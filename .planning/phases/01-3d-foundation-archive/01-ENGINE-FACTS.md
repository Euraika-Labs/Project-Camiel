## Additional Findings Beyond F1-F11

These were not asked for as separate fact rows, but were observed while producing F5 and directly change how Plan 01-03 should treat `project.godot`.

- **`config_version=6` is invalid for Godot 4.7.2 and is silently discarded, not merged.** This repository's committed `project.godot` (both before and after Plan 01-01's edits) declares `config_version=6`. Loading that file with the installed 4.7.2 engine produces `ERROR: Can't open project ..., its 'config_version' (6) is from a more recent and incompatible version of the engine. Expected config version: 5.` and the engine falls back to built-in defaults for that run — none of the file's settings are read. `ProjectSettings.save()` rewrites the header to the engine's own expected value, `config_version=5`, once any setting is changed and saved. Plan 01-03 must not assume the existing `config_version=6` line is compatible; the project settings it hand-verifies (or edits) should be checked against a `project.godot` whose `config_version` reads `5` after the engine has saved it at least once, not against the file as currently committed.
- **The engine-saved scratch scene had no `uid://` identity.** A scene produced by `PackedScene.pack()` + `ResourceSaver.save()` from a `--script` run (rather than the editor) gets no `uid="uid://..."` attribute in its `[gd_scene]` header and no sidecar `.uid` file, unlike scenes saved through the editor UI. This is why F5's `main_scene` setting stayed a `res://` path. Plan 01-03, if it wants a `uid://`-addressed main scene, will need either an editor save pass or an explicit UID-assignment step; a script-only `ResourceSaver.save()` will not produce one on its own.
