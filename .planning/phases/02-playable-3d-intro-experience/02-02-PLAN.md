<objective>
Build the one button every screen in this phase uses, and the procedurally drawn icons that go
on it.

D-16 asks for a single focusable icon-plus-label button because INTRO-05 needs an icon on each
win-screen button and the title screen, main menu and win screen all need the same activation
behaviour. D-14 is the reason it is rooted on `Button`: the inherited `pressed` signal already
absorbs a tap, a click, and Enter on the focused control, so there is exactly one code path per
activation and no second handler that can fire alongside it. The archived title screen changed
scene twice precisely because it had two.

There is no icon asset to reach for — the 2D art is deliberately unported (D-13) — so the six
icons are drawn in code. To make that provable without a display, the drawing is split: a pure
function returns the shapes for a kind, and the draw callback just renders them. The probe
asserts the shapes, which is a real assertion rather than a hope that a draw pass ran.

Purpose: this plan has no dependency on the audio work or the 3D level, so it runs beside them
in the same wave. Every later screen plan instantiates what it produces.

Output: `assets/theme/ui_theme.tres`, `scripts/ui/vector_icon.gd`, `scenes/ui/menu_button.tscn`
with `scripts/ui/menu_button.gd`, and `scripts/tools/probe_menu_button.gd`.

Decisions implemented: D-13, D-14, D-16. Visual styling follows `02-UI-SPEC.md`, which is the
locked resolution of the Claude's-Discretion styling area.
</objective>

This is the seam that makes the icons provable without a display: it is a pure function of its two arguments, touching no node state. ## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pointer and keyboard input to the button | A child's imprecise tap, click or key press reaches the component; this is the only way into the game |
| exported icon kind to the drawing code | An arbitrary string set in a scene file or by a caller selects what gets drawn |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-06 | Denial of Service | inner content nodes swallowing a pointer event | high | mitigate | `Content`, `%Icon` and `%Label` are set to ignore the mouse so every tap reaches the root `Button`; the probe's `tap_through` case asserts all three filter values and the 280 by 112 minimum size. Without this a touch or mouse-only child cannot start the game at all, which is exactly the archived Start-button defect |
| T-02-07 | Tampering | a second activation path added to the component | high | mitigate | The component declares no signal of its own and overrides no input callback; a line-anchored search across `scripts/ui` is an acceptance gate, and the probe asserts the `pressed` connection list holds exactly one entry |
| T-02-08 | Denial of Service | an unrecognised icon kind reaching the draw callback | low | mitigate | `get_icon_shapes` returns an empty array and warns for any unknown kind, so an unknown value renders nothing instead of raising during a draw pass; asserted in `all_icon_kinds` |
| T-02-09 | Tampering | icon geometry escaping the control rectangle | low | mitigate | The probe asserts every returned coordinate lies inside the requested rectangle for all six kinds, so an icon cannot paint over a neighbouring control and change what a child thinks they are pressing |
| T-02-10 | Information Disclosure | theme and component scripts | low | accept | Nothing here reads a file at runtime, opens a socket, or writes persistent storage |
| T-02-SC | Tampering | package-manager installs | low | accept | This plan performs no npm, pip or cargo install and adds no third-party asset — the icons are drawn in code and the font is the engine's built-in default, so the package legitimacy gate does not apply |
</threat_model>
