<objective>
The two lessons that never existed, and the assertion that ties the phase together.

The archived lesson 4 and lesson 5 were ten-line scripts whose ready callbacks did nothing, inside
scenes that told a child they were available. The quality gate's forbidden-phrase scan does not
catch a lie like that; only a probe that drives a lesson to a real completion does. So both lessons
here are built to a concrete rule and both are driven to completion headlessly: lesson 4 is a second
colour-recognition-and-counting task on a new colour pair, reusing lesson 1's all-three-any-order
rule and exercising that fix a second time (D-43); lesson 5 is a genuine four-step sequence on
lesson 3's activation pattern (D-44).

Lesson 5 is where this phase's one open reconciliation becomes visible. D-46 asked that one
progress-label form cover every lesson and D-44 makes this lesson four steps long. Plan 03-02
resolved it by putting the form in one file and parametrizing the total, so lesson 5 passes 4 and
its label reads `Stap: 4 / 4` while the other four read out of 3. Nothing about lesson 5's rule is
reshaped to fit a label, and there is no second format string.

The last task closes the loop on the defect that ran the longest: nothing in the archived game ever
called the progress tracker's record function, while the project's own documentation claimed it
did. Five lessons means exactly five call sites, and one probe run now drives all five to real
completions and then reads the file and asserts all five identifiers are in it.

Purpose: closes LESSON-04, LESSON-05, and LESSON-06's full five-lesson surface, and completes
PROGRESS-02 across every lesson.

Output: `scenes/lesson_4.tscn` and `scripts/lesson_4.gd`, `scenes/lesson_5.tscn` and
`scripts/lesson_5.gd`, the last two lesson table entries, and the closing assertions in both lesson
probes.

Decisions implemented: D-33, D-34, D-35, D-37, D-38, D-41, D-43, D-44, D-45, D-46.
</objective>
