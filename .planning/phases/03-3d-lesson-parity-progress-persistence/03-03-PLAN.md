<objective>
The phase's tracer: a child presses one Dutch word on the main menu, picks a lesson, plays it,
finishes it in the order that used to break it, and their result is on the disk — proved by reading
the file, not by trusting a signal.

This is the thinnest path that touches every layer this phase modifies: the main menu, a new
screen, a lesson scene, the shared target, the shared display, and the persistence layer built in
plan 03-01. Proving it end to end now means an architectural dead end costs one commit rather than
five lessons.

Two archived defects are answered here directly. Lessons 2 through 5 were unreachable because the
main menu only ever linked the first lesson, so the fix is a screen whose buttons are built from
one table and a probe that iterates that same table rather than naming a lesson. And lesson 1's
completion check tested only the red and blue tasks, so a child who did the counting task first was
locked into a lesson that could never finish — the fix is one array and a check for three, and the
probe deliberately does the counting task first.

Lesson 1's counting task is three separate objects, all of which must be gathered before the
counting task counts as one of the lesson's three tasks. That keeps D-36's check at exactly three
and D-46's label at three steps while making a child actually count to three, rather than reducing
"counting to 3" to a single touch.

Purpose: closes LESSON-01, closes LESSON-06's screen and its reachability from the menu, and closes
PROGRESS-02 for a real lesson completion. Plans 03-04 and 03-05 then add lessons 2 through 5 to the
same table and the same probes.
